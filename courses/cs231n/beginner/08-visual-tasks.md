# 08 从分类到检测与分割

> 同一张图像，可以有不同任务。不要先背模型名字，先看它需要输出什么、训练标签是什么，以及怎样评价结果。

## 1. 假设图里有两只猫和一只狗

| 任务 | 希望得到什么 | 常见标注形式 |
|---|---|---|
| 分类 | 整张图像的类别 | 类别标签 |
| 检测 | 每个对象的类别和大致位置 | 类别 + 边界框 |
| 语义分割 | 每个像素的类别 | 像素类别图 |
| 实例分割 | 每个具体对象的像素范围 | 各对象的类别与掩码 |

此前 Softmax 例子假设单标签分类。一张图允许同时标记猫和狗时，是多标签任务，不能直接把“只能选一个类别”的输出解释照搬过去。

## 2. 目标检测为什么要预测四个位置数字？

边界框 Bounding Box 可以表示为：

$$(x_{min},y_{min},x_{max},y_{max}).$$

约定图像左上为原点，x 向右增大、y 向下增大。框 `(4,6,24,28)` 的左上角是 `(4,6)`，右下角是 `(24,28)`。

按连续坐标约定，宽度为 20，高度为 22。有的旧实现采用含端点整数像素计数，公式会带 +1；不要混用约定。

检测至少需要兼顾分类和定位，可概念性地写成：

$$L=L_{分类}+\lambda L_{定位}.$$

λ 平衡不同项。实际检测器还要处理对象数量变化、预测匹配、背景与重复框等问题，不只是固定输出一个类别加四个数字。

## 3. IoU：两个框重合得怎样？

$$\operatorname{IoU}=\frac{交集面积}{并集面积}.$$

若预测框与真实框面积均为 100，交集为 60，并集为 `100+100−60=140`，IoU=`60/140≈0.429`。

为什么减去 60？两个框面积直接相加时，重叠区域算了两次。完全不重叠时 IoU=0，框完全一致时为 1。

更具体的坐标计算例子见[第九章 IoU](../notes/09-detection-segmentation.md#5-iou怎样衡量框的重合)。

**IoU 只衡量空间重合。** 框画得准但类别错了，仍不能算完整检测正确。检测评价还要考虑漏检、误检以及同一对象的重复预测。

## 4. 语义分割：每个像素分别分类

设类别 0=背景、1=猫、2=狗，一个小标签图可以写成：

$$\begin{bmatrix}0&0&0&0\\0&1&1&0\\0&1&2&2\\0&0&2&0\end{bmatrix}.$$

每个元素对应原图一个位置。对 32×32 图像、3 个互斥类别，一种输出分数形状是 `3×32×32`。

**这里的 3 是类别数，不是 RGB。** 对一个固定像素位置，读取该位置的三个类别分数，并沿类别维度做 Softmax。

一种基础损失是对有效像素的交叉熵求平均；实际任务还可能使用类别权重、忽略标签或其他损失。网络内部可以先降低分辨率，最终通过上采样、跳跃连接等得到所需输出分辨率。

## 5. 实例分割怎样区分两只猫？

语义分割把所有猫像素都标成“猫”；实例分割还要分清哪些属于猫 1，哪些属于猫 2。

一个对象的二值 mask（掩码）中，1 表示该像素属于这个对象，0 表示不属于。实例编号区分对象，不是创造了“猫 1 类”“猫 2 类”两个永久类别。

语义分割与实例分割的进一步结合会引出全景分割；具体算法与指标放在课程正文第二遍阅读。

## 6. 骨干网络与任务头

backbone（骨干网络）提取特征，head（任务头）把特征变成任务需要的输出：

```text
图像 → 特征提取网络 → 分类头：全图类别
                   → 检测头：对象类别与位置
                   → 分割头：像素类别或对象掩码
```

这是设计思路，不表示任意分类网络换掉最后一层就立刻完成检测。若先做全局平均池化，空间细节已经被汇总，定位任务通常需要读取保留空间布局的特征。

## 7. 可视化不是像素级正确答案

CAM、Grad-CAM 等方法把类别相关的响应画在图像上，帮助观察网络依赖的区域。但热图不是精确分割标注，也不能仅凭颜色证明模型有可靠的因果理解。它与前面距离矩阵的热图含义也不同，要先读颜色代表什么。

## 复习时记住

**输出要求决定标签、任务头、损失与评价。** 网络主体可能复用，但“分类准确率高”不等于框或掩码也正确。
