## 1. 从固定标签到自然语言监督

传统分类器最后一层对应一组预先定义的类别。语言能表达更多信息：对象、属性、数量、关系、场景与动作，因此图文配对可以成为更灵活的训练信号。

但网上图片的文字并不一定完整描述图像，也可能描述背景故事、只提及部分对象，甚至与图像无关。因此规模大不等于监督没有噪声。

本章先看“把图文放进同一个空间”，再看“把图像接到语言生成模型”。这两种模型的能力不同。

## 2. CLIP：双编码器与相似度矩阵

图像编码器得到 v_i，文本编码器得到 t_j，通常分别归一化。对 B 对图文：

$$S_{ij}=v_i^Tt_j/\tau.$$

S 是 B×B 矩阵，对角线对应配对图文，其他位置对应非配对候选。图到文损失为：

$$L_{I\to T}=-\frac1B\sum_i
\log\frac{e^{S_{ii}}}{\sum_j e^{S_{ij}}}.$$

文到图则沿另一维度分类，再取两个方向的平均。注意第二个方向不是重新使用同一行 softmax，而是让文本查询图像。

![图文匹配矩阵](../assets/remaining/16-clip.png)

图中对角线较大只是人为构造的成功匹配示例，不是真实模型实验。

B=2 时，每幅图在两段文字之间选搭档；B 增大后会遇到更多竞争项。可是同批不同配对也可能语义一致，因此非对角线不等于“语义一定错误”。

## 3. 零样本分类怎样实现？

设目标类别为猫、狗、车，把每个类别写成文本提示，例如“a photo of a cat”，用文本编码器得到类别向量。

给测试图像提取 v，计算它与各类别文本向量的相似度，选择最大者。这不需要为这组类别重新训练一个普通分类头。

例如相似度 [0.8,0.2,0.1]，模型选择猫。若再通过温度 softmax 得到分数分布，该分布也不自动成为校准的真实概率。

“零样本”是相对于目标任务的显式训练设置，不意味着预训练数据绝对没出现过相关概念或近似样本。评估仍需考虑数据污染。

Prompt ensemble 使用多个措辞得到类别表示并聚合，可能减轻单一文本表达的偏差。但输入措辞会影响结果，不能认为类别名字的所有写法完全等价。

## 4. 双编码器的优势与局限

图像和文本可独立编码、预先建立向量索引，检索时只计算相似度，效率高。它也天然支持开放词汇的候选描述。

但全图一个向量可能难以精确区分组合关系，例如“黑猫和棕狗”与“棕猫和黑狗”。全局配对损失未必充分约束哪个属性属于哪个对象。

细粒度计数、空间关系、文字识别与详细定位也可能需要更强的监督或不同架构。不能把“图文相似”直接等同于“能回答所有视觉问题”。

### 同一张图片，CLIP 与生成式 VLM 怎样给答案？

假设图里是一只躺在椅子上的猫。

- 给 CLIP 三段候选文字“猫”“狗”“汽车”：它比较图像与三段文字的向量相似度，选最匹配者。
- 给生成式 VLM 问句“猫在哪里”：它结合图像和问题，逐个产生回答 token，例如“在椅子上”。

**匹配候选描述与生成完整句子，是两种输出机制。** CLIP 可以通过更细的候选句子来比较描述，但它的基础双编码器不会因此自动变成逐词回答的语言生成模型。

## 5. 生成式 VLM：让语言模型读到视觉 token

一个常见结构：

$$\text{图像}\rightarrow\text{视觉编码器}\rightarrow
\text{连接模块}\rightarrow\text{语言模型}.$$

视觉编码器往往输出多个 patch 表示，连接模块把其维度和语义空间适配到语言模型，再与文本 token 共同参与生成。

训练目标常是条件语言建模：

$$L=-\sum_t\log p_\theta(w_t\mid w_{<t},I,\text{指令}).$$

这里预测的是回答 token，不是固定类别编号。哪些 token 参与损失、哪些模块被冻结、如何处理高分辨率图片，都属于具体训练配方。

### LLaVA 路线

课件通过 LLaVA 说明视觉编码器、投影连接与语言模型的组合，以及对齐和视觉指令微调的思路。训练阶段设计会随版本变化，不能把某个版本的冻结策略当作所有 VLM 的定义。

使用 patch 表示比只有全局图像向量保留更多空间信息，但并不保证语言模型一定正确利用每个位置。

## 6. Flamingo：通过跨注意力接入视觉信息

Flamingo 引入可学习的视觉重采样与跨注意力结构，让文本生成位置读取图像或视频特征。

Perceiver Resampler 将可变数量的视觉特征压成固定数量的表示，控制后续成本；语言模型中的门控跨注意力则调节视觉信息的注入。

这和“把所有图像 patch 直接当成普通文本 token 拼进去”是不同连接路线。两者都要处理图文顺序、可见范围和资源成本。

多模态 in-context learning 指在输入上下文中给若干示例后完成新任务，不意味着每次都做梯度更新。

## 7. Molmo 与 PixMo：数据设计同样是模型设计

课件介绍 Molmo 与其数据构建思路，强调高质量详细描述、指向定位和更开放的训练资料。

对初学者最重要的不是背某个历史榜单名次，而是理解监督粒度：一句笼统标题、详细区域描述、物体点坐标，给模型提供的信息完全不同。

让模型在计数时指出每个对象，可以把语言回答与图像位置联系起来，便于检查遗漏或重复。但有定位输出也不保证推理过程完全可解释或必然正确。

语音描述转录等标注流程是获取详细数据的方式，不表示所有自动转录都没有错误。

## 8. 为什么 SAM 会出现在视觉语言这一讲？

本讲不只讨论文字生成，也讨论可被灵活提示与复用的视觉基础模型。

SAM 接收图像及点、框、掩码等提示，输出候选分割掩码。典型结构有图像编码器、提示编码器和掩码解码器。

一个点可能落在“人”“衣服”“衣服上的图案”等多个合理区域中，因此提示本身可能有歧义。多掩码输出与质量估计用于应对这种不确定性。

**原始 SAM 并不是直接回答任意自然语言问题的聊天模型，也不自带所有对象的语义类别识别。** 如果系统用文字寻找对象，再把框交给 SAM，这是多个组件组合后的能力。

## 9. 视觉程序组合：把任务拆成可执行步骤

课件中的 VisProg 使用语言模型生成程序，调用视觉模块完成组合任务，例如检测对象、裁剪区域、查询属性、比较结果。

一个原创的逻辑例子：“两张图中哪张有更多杯子？”可以拆成对图 1 检测、对图 2 检测、分别计数、比较。

这种方法把某些中间步骤显式化，但会积累各模块的错误：检测漏掉杯子，程序再正确计数，也会得到错误结果。语言模型生成的程序还可能误用接口或判断条件。

程序可见提供了检查入口，不等于整个结果已经可靠。

## 10. 幻觉、定位与评估

视觉语言模型可能根据常识生成图片中不存在的细节。原因可能包括视觉分辨率、数据偏差、语言先验过强或目标与评估不匹配。

需要区分：

| 维度 | 要看什么 |
|---|---|
| 语言流畅性 | 回答是否自然 |
| 视觉忠实性 | 是否由图片支持 |
| 定位准确性 | 指向、框或区域是否正确 |
| 组合推理 | 属性、数量、关系是否绑定正确 |
| 鲁棒性 | 换视角、提示、分布后是否稳定 |

流畅描述可以完全不忠实于图片。评估时还应区分开放式问答、选择题、检索、分类和定位，它们的分数不能互换。
