## 1 为什么要从零构建语言模型

调用聊天模型时，我们输入一句话，得到一段回答。但中间仍有许多问题：输入怎么表示，网络怎么算，参数从哪里来，模型为什么选这个词，训练为什么需要这么多显存？

官方讲义指出，研究者从自己实现模型，逐渐转向下载模型、微调模型和调用 API。抽象提高了使用效率，却也让底层机制离使用者更远。CS336 的学习方式是亲手构建组件，用可观察、可运行的计算理解技术。

### 小模型能教会什么

本讲将知识分成三类：

| 类别 | 含义 | 学习时怎样理解 |
|---|---|---|
| Mechanics 机制 | Transformer、优化、并行等具体怎样工作 | 用小实现看清数据和计算路径 |
| Mindset 思维方式 | 重视效率、资源核算和规模变化 | 每次实验都问它花了多少资源 |
| Intuitions 经验判断 | 哪种结构、数据和设置效果更好 | 在对应规模和设置下检验，避免直接外推 |

小模型可以帮助我们掌握机制，也能训练分析资源的习惯。但“小模型上某个设置更好”不保证“大模型上也更好”，因为计算构成、训练动态和数据需求可能改变。

**亲手构建的目标是理解各个决定的理由，以及这些理由在哪些条件下成立。**

## 2 语言模型怎样描述文字

以下概率与训练算例是帮助理解课程总览的教学补充，本讲尚未深入推导神经网络训练。

### 从补一句话理解预测

看到前缀“今天的天气很”，我们可能接“好”“冷”“热”。语言模型为可能的下一个 token 分配概率。例如，假设一个教学词表里只有三个候选：

| 候选 | 概率 |
|---|---:|
| 好 | 0.6 |
| 冷 | 0.3 |
| 热 | 0.1 |

三项加起来等于 1。这里每个候选恰好是一个汉字，只是为了看懂概率；真实 tokenizer 可能把文字切成其他片段。

**语言模型直接输出的是候选概率，生成程序再根据这些概率选择下一项。** 可以选概率最大的项，也可以随机采样，随后把选出的内容放回前缀继续预测。

### 一整段文字的概率

把 token 序列记为 \(x_1,x_2,\ldots,x_T\)，自回归模型按顺序描述它：

\[
p_\theta(x_1,\ldots,x_T)
=\prod_{t=1}^{T}p_\theta(x_t\mid x_1,\ldots,x_{t-1}).
\]

- \(x_t\)：第 \(t\) 个 token；\(T\)：序列长度。
- \(\theta\)：模型的可学习参数。
- \(\mid\)：表示“给定”，例如给定前两项预测第三项。
- \(\prod\)：把各位置的条件概率相乘。
- 第一项的前缀为空，实际系统也可能约定起始 token。

假设一条三 token 路径的概率依次为 0.5、0.8、0.25，则整段概率为：

\[
0.5\times0.8\times0.25=0.1.
\]

这使用概率链式法则，**不要求各个 token 独立**；后面的概率明确依赖前面的内容。

### 训练与生成的区别

训练时，真实文本已经存在。用前缀预测下一项，再与真实下一项比较；反复调整参数，使真实文本获得更高概率。

```text
训练文本：我 喜欢 学习

输入前缀          监督目标
我                喜欢
我 喜欢           学习
```

本例把三个片段当作三个 token。一个常见损失是负对数似然：

\[
\mathcal L=-\sum_{t=1}^{T}\log p_\theta(x_t\mid x_{<t}).
\]

真实项的概率越大，负对数越小。上面三项的总损失是 \(-\log(0.1)\approx2.3026\)；若对三个位置取平均，则是约 0.7675。求和与平均是不同的约定。

生成时，后面的真实内容未知：模型预测，程序选择，再把结果加入前缀。这里通常保持模型参数固定。**训练在改参数；生成在用参数计算并选择输出。**

## 3 语言模型发展的主线

官方讲义从早期统计语言模型讲到神经模型、预训练模型和更大规模的通用模型。初学时抓住问题怎样变化，比记住全部模型名字更有帮助。

| 阶段 | 主要思路 | 与后续内容的关系 |
|---|---|---|
| N-gram 等统计模型 | 根据有限长度的上下文统计下一项 | 建立条件概率的基本任务 |
| 神经语言模型和 LSTM | 学习连续表示，用网络处理序列 | 用参数共享表达更多上下文关系 |
| Attention 和 Transformer | 计算序列位置之间的依赖 | 构成后续建模的核心机制 |
| 预训练与迁移 | 先从大量文本学习，再用于下游任务 | 将通用表示与具体使用联系起来 |
| 更大规模与提示使用 | 用提示表达任务，探索规模与能力的关系 | 让计算预算、数据和推理效率更重要 |
| 对话与代理系统 | 模型结合对话格式、工具和执行流程 | 需要同时理解模型与外围系统 |

BERT 等模型的训练目标与本文的自回归预测不同；表格描述发展关系，不表示所有语言模型都采用相同目标。

### 开放权重与完整开放的区别

拿到模型权重，可以加载模型做推理，但未必能复现训练。复现还需要结构、训练代码、数据来源、处理流程和训练设置。官方讲义因此区分开放权重和开放更多构建细节的模型。

这一点与课程目标直接相连：我们希望理解模型怎样形成，而不仅是知道怎样加载它。

## 4 五个课程单元怎样连接

第一讲的五个单元是一条完整构建流程。[官方课程与作业说明](https://cs336.stanford.edu/)

| 单元 | 核心问题 | 要理解的组件 |
|---|---|---|
| Basics 基础 | 怎样得到一个能训练和生成的模型 | tokenizer、Transformer、损失、优化器、训练循环 |
| Systems 系统 | 怎样让相同计算更快并容纳更大模型 | GPU kernel、内存、并行、推理 |
| Scaling 扩展规律 | 大规模训练前怎样选择设置 | 小规模实验、规律拟合、预算分配 |
| Data 数据 | 模型应该学习什么材料 | 提取、过滤、去重、混合、评价 |
| Alignment 对齐 | 怎样让模型更符合目标行为 | 示范微调、偏好、奖励与强化学习 |

### 系统效率怎样影响学习

模型需要将数据从存储位置搬到计算位置，再完成计算。即使运算公式相同，频繁搬运数据也可能拖慢执行。Kernel 可以先理解为在 GPU 上执行的计算程序；融合操作可以减少一些中间结果的反复读写。

多 GPU 并行还需要协调计算与通信。推理则要考虑提示处理和逐 token 生成两种阶段。第一讲给出这些问题的地图，具体实现将在后面展开。

### 数据与对齐分别在改变什么

网页原始内容包含导航、广告和重复文本，不能直接当成同等质量的训练材料。处理数据是在决定模型把资源花在哪些内容上；评价帮助判断这些内容和训练方法是否产生了目标能力。

预训练的下一项预测可以从文本自身获得目标。后训练还可以利用优质示范、偏好比较或可验证的回答结果，让模型更偏向期望的行为。**预测文本、遵循指令与回答正确之间需要训练与评价的连接，不能直接视为同一件事。**

## 5 为什么效率是贯穿全课的主线

资源包括计算量、显存、通信带宽和数据。在固定预算下，浪费资源意味着少处理一些有用数据，或少尝试一些设置。

讲义用“效果由效率和资源共同影响”的关系提醒读者：能随规模扩展的算法很重要。这是一种研究视角，不是把准确率严格写成乘法的物理定律。

### 用一个预算公式看清取舍

本讲给出常用粗略估计：

\[
C\approx6ND.
\]

其中 \(C\) 是训练浮点运算次数 FLOPs，\(N\) 是模型参数数量，\(D\) 是训练处理的 token 数量。系数 6 来自特定假设下的前向与反向计算估计，不能用于精确核算所有结构、序列长度和训练开销。

**教学算例：**若 \(N=10^6\)、\(D=10^8\)，则 \(C\approx6\times10^{14}\) FLOPs。预算固定时，把参数数量翻倍，按此估计就需要把 token 数量减半。

因此更大的模型不一定是预算下更好的选择。Scaling laws 通过多个较小规模实验，拟合模型大小、数据量、计算量与损失的关系，再预测较大规模的合适设置。外推依赖实验条件与训练配方，不能把某个经验比例视为永久常数。

## 6 Tokenization 怎样把文字接到模型上

Tokenizer 提供两个基本操作：

```python
encode(text) -> list[int]
decode(ids) -> str
```

`encode` 将文字转换成 token ID 列表；`decode` 根据词表把 ID 列表还原为文字。对本文讨论的不丢失信息的编码流程，期望满足：

```python
decode(encode(text)) == text
```

现实系统也可能进行规范化处理，此时需要明确还原的是原文还是规范化后的文本。

### Token ID 与向量的区别

假设教学词表中 `猫` 的编号是 7，`狗` 的编号是 8。这些数字用来索引词表；7 和 8 接近，不表示猫狗的语义一定接近。

进入网络时，常用 embedding 表把编号转换为向量：

```text
原始文本
   ↓ tokenizer.encode
整数编号列表
   ↓ 查询 embedding 表
向量序列
   ↓ 语言模型
下一项的候选分数与概率
   ↓ 选择编号，继续生成
生成编号列表
   ↓ tokenizer.decode
输出文本
```

Embedding 是后续可学习的参数。**Tokenizer 建立文本与编号的映射；embedding 建立编号与可学习向量的映射。**

### Token 不一定是一个词

Token 可以是整个词、词的一部分、标点、带空格的片段，甚至某个 Unicode 字符的部分字节。具体切分依赖词表和规则，同一句话在不同 tokenizer 下可以得到不同序列。

空格也属于文本。例如 `hello` 与 ` hello` 是不同的字节串，可能对应不同 token。数字也可能分成几段，不能假定每个数字或每个整数总是一个 token。

## 7 字符 Unicode 与 UTF-8

以下用 `A你🌍` 区分三个容易混淆的对象。

### Unicode 码点是字符的编号

Unicode 给字符分配码点。Python 可以用 `ord` 查编号，用 `chr` 从编号还原：

```python
ord("A")   # 65
ord("你")  # 20320
ord("🌍")  # 127757
chr(20320) # '你'
```

讲义的字符级 tokenizer 就是对每个字符执行 `ord`。这直接展示原理；实际字符级模型也可以另建紧凑 ID 映射，不必把所有码点值直接当作 embedding 行号。

这里的“字符”按 Python 字符串迭代的码点理解。一个屏幕上看到的组合符号或 emoji 可能包含多个码点，因此“肉眼一个字符”和“一个码点”并不总相同。

### UTF-8 将码点编码成字节

一个字节是 8 个二进制位，共有 \(2^8=256\) 种取值，范围是 0 到 255。UTF-8 是将 Unicode 文字表示为字节序列的一种编码方式。

| 字符 | Unicode 码点 | UTF-8 十进制字节 | 字节数 |
|---|---:|---|---:|
| A | 65 | `[65]` | 1 |
| 你 | 20320 | `[228, 189, 160]` | 3 |
| 🌍 | 127757 | `[240, 159, 140, 141]` | 4 |

```python
text = "A你🌍"
ids = list(text.encode("utf-8"))
# [65, 228, 189, 160, 240, 159, 140, 141]
recovered = bytes(ids).decode("utf-8")
# 'A你🌍'
```

这段文字有 3 个码点，却占 8 个 UTF-8 字节。Python 的 `len(text)` 与 `len(text.encode("utf-8"))` 因而分别是 3 和 8。

**Unicode 描述字符编号；UTF-8 描述这些字符怎样写成字节。Token 切分则是另一个设计问题。**

## 8 字符 字节与词三种方案的取舍

### 字符级方案

每个码点作为一个 token，容易解释，也可以精确还原。不过，覆盖大量文字系统时，词表仍可能很大；长单词需要多个位置，常见词内部规律也要由模型重新组合。只收集训练中见过的字符还会遇到新字符的覆盖问题。

### 字节级方案

每个 UTF-8 字节作为一个 token，普通 token 词表只需要 256 项。任何可 UTF-8 编码的输入都能表示，不需要为新词单独增加条目。

代价是序列较长。`A你🌍` 需要 8 个位置，字节序列里的一个位置还不一定对应完整字符。生成时，任意字节序列也不保证能严格解码成有效 UTF-8；覆盖有效输入与保证所有输出有效是两个问题。

### 词级方案

把整个词映射到一个编号，常见词会比较紧凑。但词的数量庞大，罕见词难学，新造词可能不在词表中。若用同一个 `UNK` 表示所有未知词，原始拼写就丢失了。

英语也不能总靠空格切分，还要处理标点、缩写和空白；中文等语言的词边界更不适合直接按空格决定。要精确还原，还必须保留切分过程中的这些信息。

| 方案 | 基础单位 | 主要优势 | 主要代价 |
|---|---|---|---|
| 字符级 | Unicode 码点 | 直观，方便解释字符序列 | 多语言词表与序列长度的取舍 |
| 字节级 | 0–255 的字节 | 词表小，覆盖可编码的新输入 | 序列长，字符可能跨多个 token |
| 词级 | 整词或分词片段 | 常见词的序列短 | 大词表、稀有词与未知词 |
| Byte-level BPE | 字节及学习到的字节串 | 保留字节覆盖，并缩短常见片段 | 需要学习词表与合并规则 |

## 9 BPE 怎样学习常见片段

Byte Pair Encoding 的关键步骤是：**反复统计相邻 token 对，把当前最常见的一对合并成新 token。** 本节讨论讲义采用的 byte-level BPE，初始单位是字节。

训练流程是：

1. 初始词表包含 256 个单字节 token。
2. 把训练文本转换成字节 ID 列表。
3. 统计当前相邻 token 对的出现次数。
4. 选出最多的一对，分配新 ID。
5. 将这对合并，更新序列，并重新统计。
6. 达到合并次数或目标词表大小后停止。

每次加入一个新条目，所以没有额外特殊 token 时，执行 \(M\) 轮合并后的词表大小是 \(256+M\)。旧的单字节条目仍保留，以便表示没见过的输入。

### 用官方例子手算三轮

训练文本是：

```text
the cat in the hat
```

全部是 ASCII 字符，每个字符占 1 个 UTF-8 字节，共 18 个。下面用 `␠` 显示空格，方便阅读；真实字节仍是空格 32。

初始序列：

```text
t h e ␠ c a t ␠ i n ␠ t h e ␠ h a t
```

第一轮出现 2 次的对有 `(t,h)`、`(h,e)`、`(e,␠)`、`(a,t)`、`(t,␠)`。最大频次并不唯一，因此需要规定平局规则。本例沿用讲义实现，选择扫描时最先遇到的最大频次对。

**第一轮：把 `t h` 合成 `th`。** 新编号 256，对应字节串 `b"th"`。

```text
[th] e ␠ c a t ␠ i n ␠ [th] e ␠ h a t
```

两处合并，18 个 token 变成 16 个。重新统计后，`([th], e)` 出现 2 次，并按同样平局规则被选中。

**第二轮：把 `[th] e` 合成 `the`。** 新编号 257。

```text
[the] ␠ c a t ␠ i n ␠ [the] ␠ h a t
```

16 个 token 变成 14 个。

**第三轮：把 `[the] ␠` 合成带尾部空格的 `the `。** 新编号 258。

```text
[the␠] c a t ␠ i n ␠ [the␠] h a t
```

14 个 token 变成 12 个。三条规则是：

| 顺序 | 输入 ID 对 | 新 ID | 新 token 对应字节 |
|---|---|---:|---|
| 1 | `(116, 104)` | 256 | `b"th"` |
| 2 | `(256, 101)` | 257 | `b"the"` |
| 3 | `(257, 32)` | 258 | `b"the "` |

这里 `the ` 可以跨越通常的词边界，因为讲义简化实现没有预分词。带空格 token 的方向和形式不能据此推广为所有 tokenizer 的固定规则。

### 为什么叫数据驱动

我们没有告诉算法 `the` 是英语单词，也没有教授语法。它只根据训练文本中的重复相邻片段建立合并规则。常见片段可能得到短表示，罕见片段则可以退回较小片段或单字节表示。

**BPE 学习的是切分与表示规则，没有因此学会语言理解。** 频繁片段也不一定对应人类认定的词或语义单位。

## 10 BPE 的训练 编码与解码

### 训练 tokenizer

输入是训练语料；输出是词表和有顺序的合并规则。训练期间通过频次决定规则，结果依赖语料、平局规则、边界处理和特殊 token 等设置。

### 编码新文本

新文本到来后，使用已经固定的规则，不对每句话重新训练。讲义的简化实现按学习顺序逐条应用合并：

```text
新文本：the quick brown fox

先转字节
→ 应用 th 规则
→ 应用 the 规则
→ 应用 the␠ 规则
```

结果的第一个 token 是 258，其余部分在当前三条规则下保持单字节。这段文本 19 个字节，编码后 16 个 token。

未知词 `quick`、`brown`、`fox` 仍能表示，因为所有基础字节都在词表中；不需要把它们变成 `UNK`。

### 解码

按 ID 查出字节串，先拼接全部字节，再进行 UTF-8 解码：

```python
raw = b"".join(vocab[token_id] for token_id in ids)
text = raw.decode("utf-8")
```

不能默认每个 token 都能独立解码成字符。例如 `你` 的字节 `[228,189,160]` 被分成三项时，每项单独都不是完整 UTF-8 字符，合起来才是。

### 训练 tokenizer 与训练模型

| 比较项 | 训练 tokenizer | 训练语言模型 |
|---|---|---|
| 要学习的对象 | 词表与切分规则 | 神经网络参数 |
| 本例的方法 | 统计相邻对并合并 | 后续使用损失与优化器 |
| 得到的结果 | 文本到 ID 的规则 | 给定前缀预测下一项的计算 |
| 使用阶段 | 固定规则编码与解码 | 使用参数预测与生成 |

模型的 embedding 和输出类别与 tokenizer 词表绑定。训练完成后任意更换编号或词表，会改变输入、输出的含义，通常需要相应迁移或重新训练。

## 11 从 BPE 原理连接到代码

完整脚本见 [lecture01_tokenization.py](../experiments/lecture01_tokenization.py)。本节解释关键计算，脚本使用自写的教学实现，便于观察中间结果。

### 相邻对怎样统计

```python
counts = Counter(zip(ids, ids[1:]))
```

例如 `ids = [1,2,1,2]`：`ids[1:]` 是 `[2,1,2]`；`zip` 依次产生 `(1,2)`、`(2,1)`、`(1,2)`，于是前一对计数为 2，后一对为 1。

统计的是**当前 token 序列的相邻对**。合并之后，序列已改变，下轮需要重新统计，不能一直使用原始字节对的频次。

### 一对怎样合并

```python
while i < len(ids):
    if i + 1 < len(ids) and (ids[i], ids[i + 1]) == pair:
        result.append(new_id)
        i += 2
    else:
        result.append(ids[i])
        i += 1
```

`i` 指向当前位置。匹配成功时消耗两个位置，加入一个新 ID；失败时保留当前项，只前进一个位置。`i + 1 < len(ids)` 避免在最后一个位置读取不存在的下一项。

**重叠例子：**`aaa` 的两个相邻位置都是 `aa`，统计频次为 2；从左到右执行非重叠替换时，只能得到 `[aa] a`，不能把同一个中间 `a` 用两次。因此计数与实际可执行替换数有时不同。

### 新编号怎样知道原文

```python
vocab[new_id] = vocab[pair[0]] + vocab[pair[1]]
```

这里 `vocab` 是字典：键是整数编号，值是字节串。假设两项分别表示 `b"th"` 与 `b"e"`，相加得到 `b"the"`。这个字典使解码不必重新推理历史合并路径。

### 运行与结果

在仓库根目录运行：

```bash
python3 courses/cs336/experiments/lecture01_tokenization.py
```

脚本核对混合文字的码点与字节、三轮合并、训练文本和新文本还原、空输入、换行以及重叠对处理。关键结果为：

```text
A你🌍：3 个码点，8 个 UTF-8 字节
三轮新 token：th → the → the␠
训练文本：18 个字节 → 12 个 token
新文本：19 个字节 → 16 个 token
decode(encode(text)) 与原文相同
```

这些结果验证教学 tokenizer 的计算，尚未训练神经语言模型，也不能用于判断实际模型效果。

## 12 词表大小 序列长度与计算成本

### Bytes per token 衡量什么

讲义用下面的比值描述文本表示的紧凑程度：

\[
r=\frac{\text{原始 UTF-8 字节数}}{\text{token 数}}.
\]

原始文本固定时，比值越大，token 序列越短。训练例子中：

\[
r=\frac{18}{12}=1.5.
\]

纯字节级方案的比值是 1。空字符串的分子与分母都为 0，不能直接套用这个公式。

这不是磁盘文件压缩率：token ID 在文件里占多少位，还取决于存储格式和词表大小。这里衡量的是模型需要处理多少个序列位置。

### 序列缩短为什么可能省计算

标准密集自注意力需要考虑位置之间的两两关系，长度为 \(L\) 时，关系数随 \(L^2\) 增长。

**教学算例：**若同一段文本从 1000 个位置缩为 250 个位置，在相同其他设置下，注意力两两关系数量变为：

\[
\frac{250^2}{1000^2}=\frac{1}{16}.
\]

这只比较密集注意力的相应部分，不代表整个训练时间自动降到 1/16。投影、MLP、输出层、内存访问和硬件执行都参与总开销；某些注意力实现也避免显式存储完整关系矩阵。

### 为什么不无限扩大词表

设词表大小为 \(V\)，向量维度为 \(d\)，embedding 表通常有 \(V\times d\) 个参数。词表从 1000 增到 10000、\(d=128\) 固定时，表中参数从 128000 增到 1280000。

输出层也需要为词表中的候选计算分数；权重共享可以减少部分重复参数，但不会消除候选计算。大词表还可能包含大量稀有条目，每项获得的学习机会较少。

**Tokenizer 的设计需要平衡序列长度、词表成本、覆盖能力和数据分布。** 更高的 bytes per token 不能单独证明模型更好。

## 13 简化 BPE 到实际 tokenizer 还差什么

讲义最后指出，作业实现会增加特殊 token、预分词和性能优化。本节解释它们的用途。

### 预分词

Pre-tokenization 先把文本分成若干片段，再在片段内部执行 BPE。这样能限制合并跨越哪些边界，并便于统计与处理。

本章主例没有预分词，所以学习到 `the `。使用不同的空白与词边界规则，结果可能不同。实际切分要结合完整 tokenizer 规则判断。

### 特殊 token

特殊 token 用来表达文本之外的协议信息，例如文档结束、角色或任务边界。具体名称与编号由 tokenizer 和模型约定，不能把它们当作普通字符串任意切碎。

系统还需要区分原文恰好出现的类似字符串与程序添加的结构标记，避免把内容误读为控制信息。

### 合并顺序与性能

本章按学习顺序遍历全部合并规则，适合短文本演示。实际实现可只处理当前相关的候选，使用规则的优先级选择合并，并优化计数和更新。

**“直接找当前最长的词表项”并不普遍等价于 BPE。** 编码必须遵循该 tokenizer 的合并规则、优先级与边界设置。

### 多语言与数据分布

Byte-level BPE 能表示可 UTF-8 编码的文字，但不同语言未必获得同等紧凑的切分。训练语料中出现得少的模式，可能保留更多较小片段。

同样的 token 上限下，不同语言能装入的文本长度可能不同。字节覆盖保证能表示输入；它没有自动保证各语言的效率与模型能力相同。

## 14 易错点与要点回顾

| 容易混淆的说法 | 正确理解 |
|---|---|
| Token 就是一个词 | Token 可以是词、词片段、空白、标点或部分字节 |
| ID 接近说明语义接近 | ID 是索引，语义表示主要由模型参数学习 |
| Unicode 与 UTF-8 是同一层概念 | 一个描述字符编号，一个描述字节编码 |
| BPE 每轮都合并原始字符对 | 合并后要在新的 token 序列上重新统计 |
| 每句新文本都重新训练 tokenizer | 编码使用训练后固定的词表和规则 |
| 一个 token 总能独立还原成字符 | Byte-level token 可能只覆盖字符的一部分字节 |
| 未知词无法编码 | 完整字节基础词表可以退回小片段表示 |
| 词表越大越好 | 还要考虑参数、候选计算与稀有条目 |
| 小模型经验可以直接推广到大模型 | 机制可帮助理解，效果判断需在对应规模检验 |

本章的关系可以串成一句话：**先用 tokenizer 把文本变成编号序列，再让模型学习序列的条件概率；切分、模型、数据和系统共同决定资源怎样被使用。**

### 自测与解析

**1. `你` 的码点是 20320，为什么字节级表示是三个数？**

码点是 Unicode 编号；UTF-8 将这个码点写成三个字节 `[228,189,160]`。码点与字节属于不同表示层。

**2. 三轮 BPE 后，为什么 `quick` 仍能编码？**

初始 256 个单字节 token 没有被删除。没有相应合并规则时，该词仍按字节表示。

**3. 训练文本为什么从 18 个 token 变成 12 个？**

三轮分别合并两处非重叠匹配，每轮减少 2 个位置，因此 \(18-2-2-2=12\)。

**4. 学会 BPE 后，模型就能回答问题了吗？**

BPE 只给出表示规则，还需要模型参数、训练数据、训练目标与训练过程。tokenizer 本身不承担回答生成。

**5. 怎样检验这一讲已经理解？**

能把文本、字节、token、ID 与 embedding 的区别讲清；能按给定规则手算合并；能解释训练和编码的区别；能读懂脚本并解释它为何先拼接字节再解码。
