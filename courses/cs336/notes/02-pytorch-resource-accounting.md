## 1 张量是怎样的数字数组

Tensor 可以先理解为按若干个轴组织的数字数组。标量只有一个数；向量是一列有序的数；矩阵按行和列组织；更多维度则可以表示更多层次的分组。

| 对象 | 教学例子 | shape | 轴数 |
|---|---|---|---:|
| 标量 | 一个损失值 | `()` | 0 |
| 向量 | `[1,2,3,4]` | `(4,)` | 1 |
| 矩阵 | 2 行，每行 3 个数 | `(2,3)` | 2 |
| 三维数组 | 2 个矩阵，每个 3 行 4 列 | `(2,3,4)` | 3 |

这里的 rank 指轴数，不是线性代数里“矩阵的秩”。`(2,3,4)` 有三个轴，总元素数为 `2×3×4=24`，不是三个元素。

### 形状的数字需要对应含义

第一讲的一个文本样本被编码为一串 ID。如果一次处理 B 条文本，每条取 S 个 token，输入 ID 通常是：

```text
(B, S)
B：批次中样本的数量
S：每条序列处理的 token 位置数
```

查 embedding 后，每个 ID 被一个 d 维向量替代，结果形状是 `(B,S,d)`。例如 B=2、S=3、d=4，包含 2 条序列，每条 3 个位置，每个位置 4 个特征值，共 24 个数字。

```text
样本 0
  位置 0 → [a, b, c, d]
  位置 1 → [e, f, g, h]
  位置 2 → [i, j, k, l]

样本 1
  位置 0 → [m, n, o, p]
  位置 1 → [q, r, s, t]
  位置 2 → [u, v, w, x]
```

本例的字母只是位置标签。若 `x.shape == (2,3,4)`，`x[1,2,0]` 表示第二个样本、第三个位置、第一个特征，因为 Python 索引从 0 开始。

### 同一种容器可以承担不同职责

官方讲义列出数据、参数、激活、梯度和优化器状态。它们都可以用张量保存，但用途不同：

| 张量类型 | 含义 | 例子 |
|---|---|---|
| 数据 | 当前送入模型的输入或目标 | token ID、真实下一项 |
| 参数 | 训练要调整的数值 | embedding 表、矩阵权重 |
| 激活 | 前向计算的中间结果 | 一层输出的特征 |
| 梯度 | 损失对数值的变化率 | 损失对权重的导数 |
| 优化器状态 | 更新算法保存的历史信息 | 梯度平方累积、移动平均 |

**激活数量会随当前输入增多；参数数量通常由模型结构决定。** 不应将一层输出的所有数字都算作模型参数。

## 2 PyTorch 张量的三个基本属性

PyTorch 是用于张量计算和自动求导的库。每个张量先关注三个属性：

| 属性 | 回答的问题 | 例子 |
|---|---|---|
| shape | 数字怎样分组 | `(2,3,4)` |
| dtype | 每个元素用什么数值格式存储 | `float32`、`bfloat16`、`int64` |
| device | 数据位于哪里 | CPU、CUDA GPU、支持时的 MPS 设备 |

下面是教学代码片段，解释 PyTorch 的基本接口：

```python
import torch

x = torch.zeros(2, 3, 4, dtype=torch.float32)
print(x.shape)          # torch.Size([2, 3, 4])
print(x.ndim)           # 3
print(x.numel())        # 24
print(x.element_size()) # 4 字节
print(x.device)         # 默认通常为 cpu
```

`zeros` 创建全零张量；`numel` 计算元素总数；`element_size` 返回一个元素的存储字节数。整数 ID 与浮点特征通常使用不同 dtype。是否参与求导也需要单独设置，不能仅凭“是张量”就认定会计算梯度。

## 3 形状与 dtype 怎样决定内存

对一个普通稠密张量，逻辑数据大小是：

```math
M=\left(\prod_i s_i\right)b.
```

`s_i` 是各轴长度，`b` 是每元素字节数。教学例子 `(2,3,4)` 有 24 个元素：float32 占 `24×4=96` 字节，bfloat16 占 `24×2=48` 字节。

这里计算的是张量元素本身，不包含 Python 对象、分配器、额外缓冲区等开销。多个视图也可能共享同一块底层存储，所以把所有视图的逻辑大小直接相加不一定是实际独占内存。

### 浮点格式的范围与精度

浮点数用符号、指数和有效数部分近似表示数值。指数主要影响可以覆盖的数量级，有效数部分主要影响同一数量级内能分辨多细。

| 格式 | 每元素存储 | 指数位数 | 存储的小数部分位数 | 主要特点 |
|---|---:|---:|---:|---|
| float32 | 4 字节 | 8 | 23 | 范围较宽，分辨率较高 |
| float16 | 2 字节 | 5 | 10 | 存储更小，但范围较窄 |
| bfloat16 | 2 字节 | 8 | 7 | 数量级范围接近 float32，分辨率更粗 |

官方例子中，`1e-8` 转成 float16 会下溢到 0；转成 bfloat16 仍可得到非零近似值。能表示很小的数量级，不表示可以精确保留任意小差异：**范围与精度是两件事。**

### 混合精度

把全部张量改成低精度可能影响稳定性。混合精度根据操作特点安排格式：一些矩阵计算和激活使用较低精度，某些累积与敏感操作使用较高精度。讲义用 bfloat16 参数、梯度、激活与 float32 优化器状态说明资源取舍，具体训练配置会不同。

PyTorch autocast 是按操作选择计算格式的机制，不表示进入上下文后创建的所有张量都自动变成 bfloat16。参数的存储 dtype、运算 dtype 与累积 dtype 需要分别检查。

### 更低精度格式

本讲还介绍 FP8 和 NVFP4，用更少位数表示数值。不同 FP8 格式在范围与分辨率之间取舍；NVFP4 还结合分块尺度。尺度、元数据、硬件和库的支持都会影响实际成本，不能只用“每值四位”推断整个训练占用。

初学时先掌握 float32、float16、bfloat16。低精度的共同原则是：减少存储和搬运，换取数值表示上的限制，需要验证训练效果。

## 4 CPU 与 GPU 上的张量

CPU 内存和 GPU 显存是不同位置。要在 GPU 上计算，通常需要把输入、权重放到兼容设备，并用相应的计算实现。

```python
if torch.cuda.is_available():
    x = x.to("cuda")
```

`.to` 返回转换后的张量，通常需要接住返回值。CUDA 面向 NVIDIA GPU；Apple 设备若支持 MPS，使用的是另一种后端，不能照搬 CUDA 性能数字或 API。

GPU 有很多并行计算资源，但张量传输、操作启动和同步也耗时。小计算、频繁传输可能无法发挥 GPU 优势。

CUDA 操作通常异步提交。只测量 Python 发起调用所用的时间，可能没有等 GPU 完成工作。官方计时函数在适当位置同步 CUDA；真实基准还需考虑预热、重复测量、精度和实际设备。

## 5 矩阵乘法怎样连接输入与输出

使用行向量样本约定：输入 X 的形状是 `(B,d_in)`，权重 W 是 `(d_in,d_out)`，输出 Y 是 `(B,d_out)`。

```math
Y=XW,\qquad
Y_{b,j}=\sum_{i=1}^{d_{in}}X_{b,i}W_{i,j}.
```

每个输出元素是输入的一行与权重的一列做点积。教学例子：

```text
X = [1 2 3]       W = [1 0]
    [4 5 6]           [0 1]
                      [1 1]

X.shape = (2,3)
W.shape = (3,2)
```

左上输出是 `1×1+2×0+3×1=4`；右上输出是 `1×0+2×1+3×1=5`，因此：

```text
Y = [ 4  5]
    [10 11]
```

`X @ W` 表示矩阵乘法；`X * W` 通常是逐元素乘法，含义不同。矩阵乘法的内侧维度必须匹配。

对于 `(B,S,d_in)`，右乘同一个 `(d_in,d_out)` 矩阵，可以得到 `(B,S,d_out)`：每个样本的每个位置都使用相同权重。B 或 S 增大时，计算和激活增多，但这一个 W 的参数数目不变。

## 6 einops 怎样使维度含义明确

官方讲义用 einops 为轴命名，让形状操作对应语义。[einops 官方文档](https://einops.rocks/api/einsum/)

### einsum 保留哪些轴 求和哪些轴

矩阵乘法可以写成：

```python
from einops import einsum
y = einsum(x, w, "batch in_dim, in_dim out_dim -> batch out_dim")
```

逗号前后描述两个输入，箭头后描述输出。`in_dim` 在输出里消失，所以沿它求和；`batch` 与 `out_dim` 保留。

两个输入都是 `(B,S,d)`，若要计算同一批次中两个序列的位置两两点积：

```python
z = einsum(x, y,
           "batch seq1 hidden, batch seq2 hidden -> batch seq1 seq2")
```

输出是 `(B,S,S)`，沿 `hidden` 求和。`seq1` 和 `seq2` 名字不同，代表输出中两个独立位置轴；不是将每个位置只与同位置配对。

### reduce 聚合一个轴

```python
from einops import reduce
y = reduce(x, "batch seq hidden -> batch seq", "sum")
```

输入 `(B,S,d)`，沿特征维求和，输出 `(B,S)`。如果选择 `mean`，则是平均而非求和。聚合哪个轴由任务决定，代码能运行并不证明轴选得对。

### rearrange 拆分或重排轴

```python
from einops import rearrange
y = rearrange(x, "batch seq (heads head_dim) -> batch seq heads head_dim",
              heads=2)
```

若输入 `(2,3,8)`，最后的 8 被拆为 `2×4`，输出 `(2,3,2,4)`。这一步保留元素总数，并没有凭空创造新特征。不同轴排列决定各元素在哪个位置；不能认为所有 reshape 和 transpose 都等价。

## 7 FLOPs 怎样计算

FLOP 是一次浮点运算；FLOPs 是运算次数；FLOP/s 是每秒运算吞吐。乘加通常按两个 FLOPs 计数，即使硬件可能用一条融合指令完成。

对 `(B,d_in) @ (d_in,d_out)`，每个输出有 `d_in` 次乘法和 `d_in−1` 次加法，共 `2d_in−1` 次。输出有 `B×d_out` 个元素：

```math
F_{exact}=B d_{out}(2d_{in}-1),\qquad
F\approx2B d_{in}d_{out}.
```

第 5 节的小例子精确计数为 `2×2×5=20`，常用近似为 `2×2×3×2=24`。大维度下忽略的差值相对较小；小例子要区分精确值与近似值。

这一层无偏置时，参数数量 P=`d_in×d_out`，所以前向约为 `2BP` FLOPs。加偏置、激活函数和其他运算需要另外计入。

### 运算次数怎样换成时间

```math
t\approx\frac{F}{P_{peak}\times u}.
```

`P_peak` 是对应设备、精度与运算类型下的峰值 FLOP/s，`u` 是实际利用比例。这是估计，不能把硬件宣传峰值直接当作所有操作的实际速度。

讲义以 MFU 表示模型运算吞吐与对应峰值的比值。统计口径需要一致，稀疏峰值、密集运算、不同精度不能混用；额外重计算和通信也影响真实用时。

## 8 算术强度怎样判断瓶颈

完成运算前要从内存读取数据，之后还需要写回结果。这里主要讨论 GPU 内部的显存读写，不要与 CPU 到 GPU 传输或 GPU 间通信混为一谈。

算术强度为：

```math
I=\frac{F}{Q}.
```

F 是运算次数，Q 是需要跨所分析内存层次搬运的字节数，单位是 FLOPs/byte。硬件的计算与带宽比为：

```math
I_* = \frac{P_{peak}}{BW}.
```

BW 是该内存层次的带宽，单位 bytes/s。理想化地假设计算和搬运能充分重叠：

```math
t\geq\max\left(\frac{F}{P_{peak}},\frac{Q}{BW}\right).
```

如果 `I<I_*`，搬运时间更大，通常称 memory-bound；如果 `I>I_*`，计算时间更大，通常称 compute-bound。实际还有启动开销、访存模式、缓存与并行度影响，这个模型用于定位主要限制。

### 用讲义的设备假设观察运算

以下均是讲义的 bf16、理想读写和 H100 吞吐假设，不是本机性能测量。讲义采用峰值 `989.5×10^12 FLOP/s`、带宽 `3.35×10^12 bytes/s`，阈值约为 `295.37 FLOPs/byte`。

| 运算 | 估计运算次数 | 估计字节搬运量 | 算术强度 |
|---|---|---|---|
| ReLU 逐元素 | n 次比较，按讲义计数 | 读 n 个、写 n 个：4n 字节 | 约 1/4 |
| GELU 逐元素 | 讲义粗估 20n，依近似实现变化 | 4n 字节 | 约 5 |
| 两向量点积 | 2n−1 | 两向量与标量输出：4n+2 | 约 1/2 |
| 向量乘 n×n 矩阵 | n(2n−1) | 2n²+4n | 约 1 |
| n×n 矩阵乘矩阵 | n²(2n−1) | 输入两矩阵、输出一矩阵：6n² | 约 n/3 |

前四项强度较低。n=1024 时，矩阵乘法强度约 341.17，超过讲义阈值，理想模型下更接近计算受限。

矩阵乘法能让读入的数据反复参与许多运算，这是强度提升的重要原因；实际达到这一优势依赖数据复用和有效的实现。小矩阵、不同精度或不同硬件不一定有同样结论。

讲义用这个对比解释训练的大矩阵计算与小批量逐 token 解码的差异。大批量推理、提示处理阶段与不同模型结构还需重新核算，不能笼统地说所有推理都只受内存限制。

## 9 Roofline 怎样解释性能上限

Roofline 将上述两种限制画在同一张图上。横轴是算术强度 I，纵轴是可达到的吞吐，理想上限为：

```math
P_{attainable}\leq\min(P_{peak},BW\times I).
```

强度小时，`BW×I` 决定上限：每读取一字节做更多运算，有机会提高吞吐。强度足够大后达到计算峰值形成的平台，继续提高强度不再自动提高吞吐。

转折点是 `I_*`。在这个理想模型下，利用比例上限可写成 `min(1,I/I_*)`，但不能把它视为实测 MFU 的精确公式。

**减少运算次数与减少运行时间并非总是一回事。** 例如两个孤立的逐元素运算若都受带宽限制，运算更少不一定带来相同比例的加速；融合后读写量改变，瓶颈也可能改变。

## 10 前向 反向与参数更新

官方讲义先用一个小线性模型说明自动求导：

```text
x = [1,2,3]
w = [1,1,1]
目标值 = 5
预测值 = x·w = 6
损失 = 0.5×(6−5)² = 0.5
```

损失函数是：

```math
\mathcal L=\frac12(x\cdot w-5)^2.
```

权重第 i 项的梯度为：

```math
\frac{\partial\mathcal L}{\partial w_i}=(x\cdot w-5)x_i.
```

先对平方求导，再乘内层对权重的导数，因此得到 `[1,2,3]`。它描述当前点附近，稍微改变权重会怎样改变损失。

```python
x = torch.tensor([1., 2., 3.])
w = torch.tensor([1., 1., 1.], requires_grad=True)
loss = 0.5 * (x @ w - 5).pow(2)
loss.backward()
# w.grad 为 [1., 2., 3.]
```

`requires_grad=True` 请求跟踪相应计算；`backward()` 沿计算依赖求梯度，通常累积到叶子参数的 `.grad`。**反向传播求梯度，但它本身不执行权重更新。**

教学补充：用学习率 0.1 做一次 SGD，`w_new=w−0.1×grad=[0.9,0.8,0.7]`，预测变为 4.6，损失变为 0.08。大梯度不自动代表重要或更新后一定更好；学习率与局部变化共同决定结果。

## 11 反向为什么还需要矩阵乘法

对于 `Y=XW`，设上游梯度 `G=∂L/∂Y`，形状为 `(B,d_out)`。链式法则给出：

```math
\frac{\partial\mathcal L}{\partial W}=X^{\mathsf T}G,
\qquad
\frac{\partial\mathcal L}{\partial X}=GW^{\mathsf T}.
```

前者形状是 `(d_in,d_out)`，后者是 `(B,d_in)`。分别用于更新这一层权重，以及将梯度继续传向前一层。

前向有一次主要矩阵乘法；反向通常需要这两次主要矩阵乘法。尺寸下的近似成本分别是 `2B d_in d_out` 和 `4B d_in d_out`，总计约 `6B d_in d_out`。

因此，多层密集网络的训练粗估为：

```math
F_{train}\approx6BP.
```

P 为参数总量，B 为这里处理的数据点数。语言模型若将多个 token 位置视作数据点，则这一符号需要换成相应 token 数。对完整训练使用 `6ND` 时，N 是参数量，D 是累计处理的 token 数，不能与本章的特征维度符号混淆。

输入不需要梯度时，某些反向计算可以省略；注意力的序列两两计算、激活、损失、优化器等需要另计。长上下文、稀疏结构等条件下，这个估计不能直接充当精确成本。

## 12 深层网络 参数与优化器状态

### 模型参数怎样登记

讲义的 Block 每层先做 `XW`，再用 ReLU 把负值变为 0。`nn.Parameter` 将权重登记为模型参数；`nn.ModuleList` 登记多个子层，便于遍历参数和移动设备。

L 个层、每层 d×d 的权重、没有偏置时，参数数量为 `Ld²`。官方 d=8、L=3 的例子共有 `3×8×8=192` 个参数。ReLU 本身在这个例子中没有可学习参数。

仅把两层线性运算相接仍是线性变换；插入非线性让结构能够表示更丰富的关系。这里用于理解张量与成本，尚不是完整语言模型。

### 优化器为什么需要额外张量

最简单的 SGD 可以根据当前梯度更新参数。AdaGrad、Momentum、Adam 等方法还保存历史信息，因此训练不能只统计权重文件大小。

讲义用 AdaGrad 举例，它累计各参数历次梯度的平方：

```math
s_t=s_{t-1}+g_t^2,\qquad
w_{t+1}=w_t-\eta\frac{g_t}{\sqrt{s_t+\epsilon}}.
```

上述 epsilon 的位置沿用讲义示例；不同实现的具体约定需要核对。`s_t` 是与参数形状对应的状态，`eta` 是学习率，`epsilon` 用于避免极小分母造成问题。

讲义进一步连接 Momentum、RMSProp 与 Adam：前者跟踪梯度变化，RMSProp 对梯度平方使用移动平均，Adam 同时保存一阶与二阶信息。这里先理解状态为何存在，具体公式随后深入。

### 四类主要训练内存

```math
M_{train}\approx M_{params}+M_{grads}+M_{states}+M_{activations}.
```

在讲义的一种假设中，每个参数的权重占 2 字节，梯度 2 字节，Adam 两个 float32 状态共 8 字节，合计 12 字节，尚未算激活。

某些混合精度方案另有 float32 主权重或不同梯度格式；其他实现还有临时缓冲、分配器等成本。因此“12 字节/参数”是配置下的账目，不是所有训练的常数。

对讲义简化深层网络，激活粗估为 `2BLd` 字节；真实自动求导可能保留更多中间张量。增大批次、序列长度与层数都会影响激活峰值。

### 两个官方资源算例

讲义用 70B 参数、15T token、1024 个 H100、单卡密集峰值 989.5 TFLOP/s、利用比例 0.5 估计训练时间：约 **143.93 天**。这是假设下的量级估计，未逐项模拟通信、故障、重计算与所有结构开销。

8 张 80GB 卡共 640GB，若仅按 12 字节/参数理想分摊，则上限约 **53.33B 参数**。这要求相应内存能跨卡分片；普通数据并行通常每卡各存模型，不能直接把显存总量当成一张大卡。激活和其他开销计入后，可训练规模会更低。

## 13 训练循环怎样连接全部组件

一轮训练的步骤为：

```text
取一批输入与目标
  ↓
前向计算预测和损失
  ↓
反向计算梯度
  ↓
优化器按梯度与历史状态更新参数
  ↓
清理梯度，准备下一轮
```

PyTorch 默认会累积梯度；常规每批独立更新时需适当清理，否则上批梯度会进入下一批。清理可以在一轮开始或更新后执行，但必须与是否计划累积保持一致。

### 平均哪个轴必须明确

讲义训练演示中的 `model(x).mean()` 将整个批次和特征全部平均成一个标量，再与每个样本目标比较。这展示计算路径，但不能直接当作逐样本预测的接口。

若教学任务要求每个样本一个预测，而模型输出是 `(B,d)`，可沿最后特征轴平均，得到 `(B,)`；是否这样聚合要由任务决定。这是笔记的教学解释，不能把任何输出都随意平均后视为正确模型。

损失输入形状和目标形状不匹配时，广播可能让计算继续执行；“能运行”不保证监督关系正确。梯度和参数更新同样需要检查对象与形状。

## 14 梯度累积怎样减小激活峰值

假设想使用 64 个样本的一次更新，但一次只能处理 16 个样本。可以拆为 4 个 microbatch，分别前向与反向，将梯度累积，处理完四份才更新一次。

```text
16 个样本 → 梯度贡献 1
16 个样本 → 梯度贡献 2
16 个样本 → 梯度贡献 3
16 个样本 → 梯度贡献 4
                   ↓
               一次参数更新
```

每份反向后可以释放相应计算图，中间激活不必按完整批次同时保留；参数、梯度与优化器状态仍需存储。

**平均损失需要正确加权。** 如果四份大小相同且每份损失是样本平均，每份贡献应乘 1/4，使总梯度对应完整批次平均。大小不同则按样本数或有效 token 数加权。

只有目标可按样本或 token 分解、权重在累积期间不更新等条件下，才能匹配大批次梯度。依赖批次统计的操作或随机过程还会影响等价性；累积不保证必然提升效果。

每份都 `optimizer.step()` 代表四次小批次更新，通常不等于一次大批次更新；每份都清零梯度则无法累积。

## 15 激活重计算怎样用计算换内存

反向传播通常需要前向的中间信息。例如权重梯度 `XᵀG` 就用到 X。保存许多层的中间结果会增加内存。

Activation checkpointing 又称重计算或 rematerialization：只保存部分边界的结果，反向需要中间结果时，从保存的位置重新计算它们。

```text
普通前向：保存 h1、h2、h3、h4、h5、h6
分段保存：保存输入、h3、h6
反向时：从输入重算 h1、h2，从 h3 重算 h4、h5
```

减少的是中间结果存储，增加的是重复前向计算；没有减少模型参数。与“训练状态存到硬盘”的 checkpoint 不同，这里的目的不是断点续训。

讲义用等宽线性链分析保存间隔：若每约 `sqrt(L)` 层保存一次，边界数量与单段内部重计算所需临时激活都约为 `sqrt(L)`，激活空间可从随 L 增长降到约 `sqrt(L)`，同时付出线性量级的重计算。真实实现受分段、算子与随机状态处理影响。

无梯度推理通常无需保存供反向使用的全部中间激活，但仍可能有 KV cache、输出和临时缓冲；不能据此认为推理只占权重和一层结果。
