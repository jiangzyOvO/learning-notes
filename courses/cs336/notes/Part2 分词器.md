# 1. 前言

分词器（tokenizer）负责把原始文本切分成词元（token），再将它们映射为数字编号（token ID）。模型随后通过 embedding 层，将这些编号转换成向量，参与后续计算。

# 2. 训练分词器

训练分词器，是根据语料学习词表，以及切分文本所需的规则或参数。它通常与语言模型的训练分开进行：先准备并固定分词器，再用其编码的文本训练模型。

## 2.1 准备语料

语料应覆盖目标应用中的语言、领域和文本风格。例如，面向中文代码问答的分词器，需要关注中文、英文和代码，而不必为了“多样性”加入与目标无关的大量语言。

清洗与标准化应根据任务选择，可以包括去除无关元数据、处理乱码、去重、统一部分字符形式，以及对敏感信息进行脱敏。不能机械删除所有空白或特殊字符，例如代码中的缩进就可能携带重要信息。

例如（NER），将：

> 小明的邮箱是 test111@example.com，电话是 13312311111，现在居住于重庆两江新区的某小区。

处理为：

> [NAME]的邮箱是[EMAIL]，电话是[PHONE]，现在居住于[PLACE]。

## 2.2 预分词与基础单元

常见预分词方式包括按空格和标点切分，或者按字符类别分段。预分词得到的片段不一定是最终 token，后续子词算法还可能继续切分。

### 字符与字节作为基础单元

- **字符级基础单元**：以 Unicode 字符为起点；如果词表只保留训练中出现的字符，遇到未覆盖字符仍可能发生 OOV（词表外）问题。
- **字节级基础单元**：将 UTF-8 文本拆成字节；如果完整保留 0～255 的全部 256 种字节，就可以表示任意有效 UTF-8 文本，避免因缺少基础字符而无法编码。

纯字节表示通常会产生较长的序列。字节级 BPE 可以进一步学习常见字节组合，减少 token 数量。

## 2.3 统计并迭代

分词算法决定如何构建词表以及如何选择切分；完整分词器还包含标准化、预分词、编号映射、解码等组件。

### BPE

BPE 从基础字符或字节出发，统计当前序列中相邻 token 对的频次，每轮选择频次最高的一对进行合并，将新 token 加入词表，直到达到目标词表大小、合并次数或其他停止条件。

### WordPiece

WordPiece 也从较小词表出发构建子词词表，其训练思想与提升语料似然有关。常见教学解释使用以下评分选择候选合并：

$$
\operatorname{score}(A,B)=\frac{f(A,B)}{f(A)\,f(B)}
$$

其中，f(A,B) 表示相邻子词对的出现次数，f(A)、f(B) 表示各子词的出现次数。评分关注组合相对于两个组成部分各自频率的关联程度，不只看相邻对出现了多少次。

### Unigram

Unigram 从较大的候选词表出发，为每个 token 分配概率，并假设各 token 独立出现。一种切分的得分是其中各 token 概率的乘积：

$$
P(t_1,\ldots,t_k)=\prod_{i=1}^{k}p(t_i)
$$

训练时，同一文本可能存在多种合法切分。算法使用 EM（期望最大化）方法，在当前概率下计算 token 的期望使用次数，再更新概率，以提高训练语料的边缘似然。

随后估算删除各 token 对整体似然的影响，裁剪贡献较小的一批候选，并重新优化，直到达到目标词表大小。基础字符通常会保留，以保证已覆盖字符组成的文本仍可切分。

### SentencePiece：工具框架

SentencePiece 是分词与反分词工具，支持 BPE、Unigram 等算法，不是与这两者并列的另一种子词算法。

## 2.4 保存训练结果

训练完成后，需要保存词表、分词所需的规则或参数，以及相关配置。具体信息和文件组织取决于算法与实现。

| 算法或工具 | 需要保留的核心信息 |
| --- | --- |
| BPE | token 与 ID 的映射，以及合并规则的顺序或优先级 |
| WordPiece | 最终词表，以及词内前缀等配置；编码不需要重放合并过程 |
| Unigram | 词表，以及各 token 的概率或分数 |
| SentencePiece | 通常以 .model 文件保存标准化规则、词表及分词模型等 |

# 3. 编码、解码与模型输入

需要区分三个阶段：

- **训练分词器**：学习词表及相关规则或参数。
- **编码**：使用已有分词器，将新文本转换为 token ID 序列。普通编码不会遇到新文本就自动扩充词表。
- **解码**：根据编号恢复 token 表示，再还原文本。

词表固定后，模型通过 embedding 层把编号映射为向量。分词器与模型必须匹配；调整 token 编号或扩充词表时，还需要相应处理模型的输入嵌入、输出层和训练问题，不能只修改词表文件就认为保持兼容。
